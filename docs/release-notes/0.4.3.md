# RAG Workbench v0.4.3

PDFs take their headings from their own bookmarks, charts are no longer mistaken for flowcharts,
and pictures are described once and remembered, so older documents can be read again with the
new reading rules without describing every picture again. Search gains a document picker and an
editable query template; the Build tab shows the pictures being described; the Documents tab
lists text worth checking; and an evaluation now says whether the answer is in what the agent
actually reads.

Knowledge bases from earlier versions open, build and search unchanged.

## Reading documents

- **Headings from the PDF's bookmarks.**
  - A PDF made by Word, or by most other authoring tools, carries one bookmark per heading.
    When at least three bookmarks match lines on their pages, those lines are the headings, at the
    bookmarks' levels. A heading set in plain body type is now found, and a wrapped heading stays
    one heading.
  - A bold line without a bookmark still counts, one level under the bookmark before it.
  - Bookmarks that match nothing ("Page 1", "Page 2") are ignored, and headings come from type
    size and weight as before.
  - Headings decide the section path every chunk is embedded with, and its section in search, so
    this improves both.
- **A check on headings.** A document of five pages or more with no headings, or one with more
  headings than paragraphs, gets a note in the Documents tab and the build log: its sections and
  context in search will be weak.
- **Charts aren't flowcharts.**
  - A chart is recognised by its axes (a vertical and a horizontal line meeting at a corner) plus
    a sign of a chart around them: number labels along an axis, bars of different lengths on one
    baseline, evenly spaced grid lines, or long curves.
  - Callout boxes joined by arrows on a chart stay part of the chart, which is described as a
    picture, never turned into steps.
  - Flowcharts with filled, aligned or numbered boxes are not affected.

## Reading older documents again

- **Pictures are described once.** Each description is kept by picture in `descriptions.db` in the
  workspace folder; the key is the image, the picture model and the prompt wording. A file read
  again (a new version, new reading rules, or **Rebuild everything from scratch**) only sends
  pictures it hasn't seen to the picture model. A knowledge base built before this version fills
  the store from its own stored descriptions the first time a document is read again.
- **Read again PDF and Word files read by an older version.** The Build tab offers this when there
  are any (`rag build --reread-older` on the command line). They then get the reading rules of
  0.4.2 and 0.4.3: shared table rules, panels, text boxes, Word-shape flowcharts, bookmarked
  headings and the chart check.
  - Nothing is read again without asking: scanned pages are read with OCR again, which can take a
    while.
  - Other file types aren't affected.

## Search

- **Pick the documents to search.** The "Only documents" text box is now a list with a search
  field and checkboxes. Typed text can still be kept as a pattern ("WI-12" matches every
  document whose number or name contains it).
- **Query template (Details → Query template → Edit).** For experienced users. How a question is
  embedded, with `${query}` where the question goes: `Instruct: Given a question about our
  manuals, retrieve passages that answer it\nQuery:${query}`.
  - Only questions are embedded this way, so nothing is embedded again. Results do change, so
    compare with an evaluation before and after.
  - Each knowledge base keeps its own template. A build with a different template in the config
    is no longer refused; searches always use the knowledge base's template, and exported packs
    carry it to the retrieval server (unchanged format: `{query}` in the pack's
    `query_instruction`).
  - `query_template` in the config takes `${task}` and `${query}`; the older `{task}` and `{query}`
    still work.

## Builds and review

- **Pictures being described** show on the Build tab under the current file: the latest six, each
  with its description as it arrives, and "(described before)" when it came from the store.
- **To review (Documents tab, `rag review`).** Text read with OCR at low confidence, worst first:
  scanned pages, tables read from pictures, and text in figures.
  - Until the knowledge base has 30 such chunks, anything below 75% is listed.
  - After that, a chunk is listed when it is unusually low for this knowledge base: more than two
    standard deviations below its mean (and always below 50%).
  - Clicking one opens it in its document. Editing a chunk's text is planned for 0.5.

## Evaluation

- **Answer in what the agent reads (read@5).** Recall measures whether the right chunk ranks.
  read@5 measures whether the expected answer is in the passages actually handed to the agent: the
  top five results with their sections, procedures or neighbouring chunks. With it comes the
  average size of those passages in tokens.
  - An expectation with `contains` needs that text in a passage; one without needs a matching
    chunk among the passage's chunks.
  - This is the number to compare when changing `[search] sections`, `section_tokens` or the
    query template.
  - It is shown in the Evaluate tab, the report and `rag eval`.

## Compatibility

- Knowledge bases and packs from 0.4.x open, build and search unchanged. PDF and Word files read
  by 0.4.2 or earlier keep their reading until a build is asked to read them again.
- The engine's JSON request and response only gain fields. New engine methods are `kb.review` and
  `kb.query_template`; `kb.build` gains `reread_older`.
- `descriptions.db` stays in the workspace folder. It isn't part of exported packs, and **Rebuild
  everything from scratch** keeps it.
